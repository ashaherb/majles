# Languages and right-to-left layout

This product ships in the languages listed under **Languages** in `CLAUDE.md`.
Every agent follows the rules below. The right-to-left rules apply when any of
those languages is written right to left.

## Every language is first-class

Each language is written natively, not translated from another. A version may
use different examples where a translated one would not land.

**Why:** a translated product reads as a second-class product to the people who
use that language.

## Specs give exact copy in every language

Every empty, error and loading state, and every label, is written out in each
supported language.

## Layout is written in start and end, never left and right

One layout serves both directions, switched once at the root. Whatever the
stack, spacing, alignment and placement name the start and end of a line, not
its left and right:

- **Web:** CSS logical properties. `margin-inline-start`, never `margin-left`;
  `padding-block`, never `padding-top`; `border-inline-end`, never
  `border-right`.
- **Other stacks:** the stack's directional equivalent, for example Flutter's
  `EdgeInsetsDirectional` and `AlignmentDirectional`, Godot's `layout_direction`,
  or Android's `start`/`end` attributes. The stack ADR names which one.

A layout that needs a separate right-to-left version is built wrong. Drawing
that must not mirror, such as a game board or a chart, is an explicit, scoped
exception, not a reason to write left and right everywhere.

**Why:** one layout then serves both directions, and right-to-left can never
fall behind.

## Know what never mirrors

Numerals, Latin-script brand names, code, and icons whose meaning does not
depend on direction all stay as they are in RTL.

## Check both directions before calling anything finished

Right-to-left scripts such as Arabic set longer than English at the same size,
and need more line height. Negative letter-spacing breaks Arabic joins.

## The researcher checks every language, specifically

For any question touching the interface, content or tooling, the research checks
how each option behaves in every supported language, and in right-to-left layout
if any of them is RTL. Most
sources are English-only and silent on this. The findings say so, rather than
assuming it works.

## The critic treats one language being worse as a finding

Anything that makes the experience in one language worse than in another is a
defect, not a polish item.

## The architecture decides the i18n model in an ADR

That ADR covers everything from how strings are stored (and URL structure, on
the web) to how a translator adds a language later. It is `Needed by: slice 1`,
since every screen is built on it.
